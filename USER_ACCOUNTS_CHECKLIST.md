# User Accounts — Test Checklist

Targets the **WEB UI** of `/administration/user-accounts/` (Edsson Elements internal admin app, DevExtreme DataGrid). API-level cases are out of scope.

**Priority legend:** `critical` = blocks core usage or causes data corruption / security exposure · `high` = frequently used functionality users depend on · `medium` = secondary features & common edge cases · `low` = cosmetic / rare.

**Test-design techniques applied:** equivalence partitioning, boundary value analysis (BVA), decision tables, state transition, combinatorial/interaction, error guessing, exploratory, accessibility, performance, security, compatibility, localization.

---

## Deferred — do not implement (destructive operations)

> Ці кейси не реалізуємо поки, щоб не зламати тестові дані.

- [ ] [DESTRUCTIVE / DEFERRED] With one or more rows selected, the grid-header trash button deletes the selected user account(s) and they no longer appear in the grid after refresh (critical)

- [ ] [DESTRUCTIVE / DEFERRED] After deleting a user, its master-detail data, linked projects and group memberships are removed/cleaned up and no orphaned references remain (high)
- [ ] [DESTRUCTIVE / DEFERRED] A non-admin user cannot delete a user account; the delete mutation is rejected server-side even if the trash button is reachable in the DOM (critical)
